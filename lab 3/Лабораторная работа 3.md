# 2. Ответы на контрольные вопросы

**1. Зачем в Ч.1 использовался `--link` и почему в Compose он не нужен?**
Флаг `--link` — это старый способ заставить контейнеры видеть друг друга по именам. В Compose он не нужен, потому что Compose сам при запуске создает общую bridge-сеть для всех сервисов в файле и настраивает локальный DNS. 

**2. Чем отличается `image` от `build` в Compose?**
`image` говорит докеру просто скачать уже готовый образ из реестра (например, с Docker Hub). А `build` заставляет его собрать этот образ с нуля из локального файла `Dockerfile`.

**3. Почему нельзя масштабировать сервис с публикацией фиксированного порта на одном хосте? Перечислите способы обойти это ограничение.**
Потому что один порт на компьютере (хосте) не может быть занят двумя приложениями одновременно. Возникнет конфликт.
*Как обойти:*
1. Сделать порты динамическими (типа `"0:5000"`), чтобы Docker сам раскидывал реплики по свободным портам.
2. Поставить балансировщик нагрузки (например, Nginx). Он будет висеть на одном фиксированном порту и перенаправлять трафик на разные внутренние реплики приложения.

**4. Что делает `docker compose down -v` и чем отличается от `down` без `-v`?**
Обычный `docker compose down` просто останавливает и удаляет контейнеры и сети текущего проекта. А если добавить флаг `-v` (volumes), то он дополнительно снесет все тома с данными, зачистив всё под ноль.

**5. Как в Compose обеспечивается сетевое имя сервиса для обращения из другого сервиса?**
Когда поднимается Compose-стек, создается своя пользовательская сеть. Внутри этой сети крутится встроенный докеровский DNS-сервер, который сам привязывает имена сервисов из YAML-файла (например, `redis`) к их реальным внутренним IP-адресам.
